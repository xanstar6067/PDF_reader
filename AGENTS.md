# Карта проекта и инструкции PaperDesk PDF

## Назначение и состояние
PaperDesk PDF — настольное приложение для просмотра, печати и редактирования PDF в Windows. Интерфейс на русском языке, рабочее пространство в стиле Acrobat: навигация слева, документ в центре, инструменты справа.

## Технологии
C#, WPF, .NET 10 (`net10.0-windows`), Windows x64. PDFium (без V8/JavaScript), поставляемый пакетом `bblanchon.PDFium.Win32`, для рендеринга, извлечения текста, закладок, изменения объектов и сохранения PDF. Версия пакета фиксируется и проверяется через NuGet lock file.

## Структура
- `PDF_Reader/PDF_Reader.slnx` — решение Visual Studio.
- `PDF_Reader/PDF_Reader/PDF_Reader.csproj` — проект Windows-приложения.
- `PDF_Reader/PDF_Reader/App.xaml` и `App.xaml.cs` — запуск приложения и ресурсы.
- `PDF_Reader/PDF_Reader/MainWindow.xaml` и `MainWindow.xaml.cs` — главное окно.
- `PDF_Reader/PDF_Reader/AssemblyInfo.cs` — настройки поиска ресурсов WPF.
- `PDF_Reader/PDF_Reader/Native/` — изолированный слой P/Invoke PDFium.
  - `Pdfium.cs` — объявления ABI, с правильными размерами Windows `unsigned long` и `size_t`.
  - `FormFillSession.cs` — жизненный цикл AcroForm и удерживаемые нативные callbacks, без JavaScript.
- `PDF_Reader/PDF_Reader/Models/` — модель документа, геометрия, закладки и результаты поиска.
- `PDF_Reader/PDF_Reader/Services/` — PDF-движок, история изменений, печать, настройки и интеграция Windows.
- `PDF_Reader/PDF_Reader/ViewModels/` — состояние рабочего пространства и команды.
- `PDF_Reader/PDF_Reader/Controls/` — отображение страниц, выделение и взаимодействие с документом.
- `PDF_Reader/PDF_Reader/Views/` — диалоги и ресурсы интерфейса.
- `PDF_Reader/PDF_Reader.Tests/` — интеграционные проверки на реальных PDF, создаваемых во время теста.
- `README.md` — возможности, ограничения, горячие клавиши и установка.
- `tools/Publish.ps1` — автономная Release-публикация; `-FrameworkDependent` для сборки без .NET runtime.
- `tools/Create-AppIcon.ps1` — воспроизводимое создание иконки приложения.
- `third-party/` и `THIRD-PARTY-NOTICES.md` — полные лицензии PDFium, его компонентов и .NET, включаемые в публикацию.
- `.gitignore` — исключения для результатов сборки и локальных настроек.
- `AGENTS.md` — инструкции для работы с проектом.

## Сборка и запуск
На Windows с .NET 10 SDK:

```powershell
dotnet restore PDF_Reader/PDF_Reader.slnx --locked-mode
dotnet build PDF_Reader/PDF_Reader.slnx -c Release --no-restore
dotnet run --project PDF_Reader/PDF_Reader
dotnet run --project PDF_Reader/PDF_Reader.Tests -- artifacts/tests
.\tools\Publish.ps1
```

Публикация: `artifacts/PaperDesk/PaperDesk.exe`, переносить всю папку. Тесты не отправляют задания на физический принтер; проверяют пагинацию и рендеринг для печати. PNG интерфейса и сгенерированные PDF находятся в `artifacts/tests`. Команды WPF следует выполнять на Windows с доступным рабочим столом.

## Реализованные возможности
- Вкладки, перетаскивание файлов, открытие PDF через аргументы, `/p` для диалога печати.
- Виртуализованный непрерывный просмотр и миниатюры, масштабирование, поворот, полноэкранный режим.
- Иерархические PDF-закладки, поиск с подсветкой, регистр и слово целиком, выделение и копирование.
- Замена/удаление текстовых объектов, добавление кириллического и многострочного текста с встраиваемым Segoe UI.
- Стандартные заметки и маркер; удаление аннотаций. AcroForm: текст, флажки, переключатели, редактируемые выпадающие поля.
- Создание, вставка, перемещение, удаление, импорт и извлечение страниц.
- Атомарное сохранение, конфликт с внешними изменениями файла, undo/redo и сохранение паролей PDF.
- Печать с выбором принтера, диапазона, текущей страницы и свойств драйвера.
- Недавние документы/последняя страница; регистрация для текущего пользователя и выбор приложения по умолчанию через настройки Windows.

## Границы реализации
OCR, редактирование вложенных Form XObjects/изображений, перевёрстка абзацев, XFA, цифровые подписи и экспорт в Office отсутствуют. Замена текста сохраняет позицию/цвет/матрицу, но использует Segoe UI; длинный текст не переносится автоматически. Изменения могут нарушить существующие цифровые подписи. Печать растром в 200 DPI. Снимки истории: до 20 состояний и ориентир 128 МБ, минимум один снимок для крупного PDF. Замена текста не является инструментом безопасной redaction.

## Архитектурные правила
- PDFium не потокобезопасен: все обращения к нативному движку сериализованы общим lock; тяжёлые операции выполняются вне UI-потока.
- PDF открыт из удерживаемого буфера памяти: исходный файл не блокируется и сохраняется атомарно через временный файл в том же каталоге.
- Изменения PDF выполняются транзакционно с откатом при ошибке, ограниченной историей undo/redo и отдельным признаком несохранённых изменений.
- PDF-координаты преобразуются через PDFium, включая поворот страниц. Масштаб UI не должен влиять на координаты изменений.
- UI не обращается напрямую к P/Invoke. Нативные указатели не выходят из PDF-сервиса.
- Подключать и отключать каждую страницу в FormFillSession до закрытия PDFium page handle; callback-делегаты и структуры удерживать до закрытия form environment.
- Не считать reserved permission bits разрешением для PDF security revision 2: сборка страниц определяется правом изменения, заполнение формы — правом аннотирования.
- Обновлять ObservableCollection только в UI-потоке; импорт, поиск, чтение метаданных и рендеринг выполняются вне него. Изменение коллекции вкладок блокирует обратные callbacks выбора до завершения обновления.
- Не менять Windows UserChoice напрямую и не регистрировать ассоциации при запуске: это выполняется только по явному нажатию кнопки пользователем.
- Файлы `bin`, `obj`, `.packages`, `.dotnet_home`, `artifacts`, `.vs` и `*.user` не должны попадать в репозиторий.
