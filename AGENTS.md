# Карта проекта и инструкции PaperDesk PDF

## Назначение и состояние
PaperDesk PDF — настольное приложение для просмотра, печати и редактирования PDF в Windows. Интерфейс на русском языке, рабочее пространство в стиле Acrobat: навигация слева, документ в центре, инструменты справа.

## Технологии
C#, WPF, .NET 10 (`net10.0-windows`), Windows x64. PDFium (без V8/JavaScript), поставляемый пакетом `bblanchon.PDFium.Win32`, для рендеринга, извлечения текста, закладок, изменения объектов и сохранения PDF. Версия пакета фиксируется и проверяется через NuGet lock file.

3D: собственный нативный D3D11-рендер (`Native3D`), DXGI для выбора ГП, PdfPig 0.1.14 для чтения встроенных потоков из снимка PDF. `PaperDeskModelWorker.exe` — отдельный декодер: собственный начальный U3D reader и nanoPRC для PRC; исходники и AGPLv3 работника поставляются вместе с программой. zlib 1.3.1 поставляется в исходниках. Новые версии зависимостей не загружаются во время сборки.

## Структура
- `PDF_Reader/PDF_Reader.slnx` — решение Visual Studio.
- `PDF_Reader/PDF_Reader/PDF_Reader.csproj` — проект Windows-приложения.
- `PDF_Reader/PDF_Reader/App.xaml` и `App.xaml.cs` — запуск приложения и ресурсы.
- `PDF_Reader/PDF_Reader/MainWindow.xaml` и `MainWindow.xaml.cs` — главное окно.
- `PDF_Reader/PDF_Reader/AssemblyInfo.cs` — настройки поиска ресурсов WPF.
- `PDF_Reader/PDF_Reader/Native/` — изолированный слой P/Invoke PDFium.
  - `Pdfium.cs` — объявления ABI, с правильными размерами Windows `unsigned long` и `size_t`.
  - `FormFillSession.cs` — жизненный цикл AcroForm и удерживаемые нативные callbacks, без JavaScript.
  - `ThreeDNative.cs` и `ModelWorkerJob.cs` — D3D11 ABI/SafeHandle и ограничения отдельного процесса декодирования.
  - `PrinterProperties.cs` — изолированный вызов окна настроек драйвера через DEVMODE и безопасный printer handle.
- `PDF_Reader/PDF_Reader/Models/` — модель документа, геометрия, закладки и результаты поиска.
- `PDF_Reader/PDF_Reader/Services/` — PDF-движок, история изменений, печать, настройки и интеграция Windows.
  - `ThreeDService.cs` — извлечение U3D/PRC, ограниченный отдельный процесс декодирования, проверка геометрии, предпросмотр страницы/печати.
  - `ThreeDRenderer.cs` — владение D3D11-устройством, нормализованная геометрия, эффекты и выдача растра WPF; отдельная блокировка от PDFium.
  - `PdfDocument.cs` — документ PDFium: рендер страниц и их фрагментов, правки, история, сохранение.
  - `TrueTypeSubsetter.cs` — подмножества TrueType для встраивания (только нужные глифы, без хинтинга и таблиц вёрстки).
  - `ThemeService.cs` — системная, светлая и тёмная темы, постоянные кисти с привязанными цветами, фон композитора и заголовки Windows; цвета PDF не меняются.
  - `PrintService.cs` — асинхронная печать из копии документа и собственный предпросмотр; общий рендер листов, включая фрагменты постера.
  - `PrintLayout.cs` — физическая геометрия листов: масштаб, постер с полями/нахлёстом, несколько страниц и раскладка брошюры.
  - `PrinterSettingsService.cs` — перечисление принтеров, форматы бумаги, проверка PrintTicket, область печати и свойства драйвера.
  - `RecoveryService.cs` и `ErrorLog.cs` — резервные копии изменённых документов и журнал непредвиденных ошибок.
  - `SingleInstanceService.cs` — одно окно на пользователя: повторный запуск передаёт файлы через named pipe.
- `PDF_Reader/PDF_Reader/ViewModels/` — состояние рабочего пространства и команды.
- `PDF_Reader/PDF_Reader/Controls/` — отображение страниц, выделение и взаимодействие с документом.
- `PDF_Reader/PDF_Reader/Views/` — диалоги и ресурсы интерфейса; `MessageWindow.cs` — сообщения и подтверждения в выбранной теме; `PrintWindow.xaml` и `.xaml.cs` — собственный диалог печати с предпросмотром и картой плиток постера.
  - `ThreeDWindow.cs` и `GraphicsSettingsWindow.cs` — окно модели, эффекты/освещение и выбор адаптера; сохраняются LUID и имя ГП для повторного сопоставления после перезапуска Windows.
  - `Theme.xaml` и `ControlTemplates.xaml` — общие стили и шаблоны панелей, вкладок, списков, закладок, выпадающих списков, подсказок и контекстных меню без светлых градиентов системных шаблонов.
- `PDF_Reader/PDF_Reader.Tests/` — интеграционные проверки на реальных PDF, создаваемых во время теста.
- `README.md` — возможности, ограничения, горячие клавиши и установка.
- `tools/Publish.ps1` — автономная Release-публикация; `-FrameworkDependent` для сборки без .NET runtime.
- `Native3D/` — собственный C++ D3D11/DXGI-рендер и CMake-сборка. `tools/Build-3D.ps1` автоматически собирает DLL и отдельный работник перед сборкой C#; требуются Visual Studio C++ Build Tools и CMake. Обе нативные программы включаются в публикацию.
- `third-party/nanoprc/` — AGPLv3-декодер с исправлениями размещения PRC, исходники отдельного работника, протокол PD3D, сгенерированные регрессии `paperdesk-prc-tests.c` и самостоятельные инструкции CMake-сборки; `third-party/zlib/` и `third-party/pdfpig/` — исходники/лицензии новых зависимостей.
- `tools/Create-AppIcon.ps1` — воспроизводимое создание иконки: красный скруглённый квадрат с белой надписью PDF, размеры 16–256 пикселей. Один ресурс используется для EXE и окна WPF.
- `third-party/` и `THIRD-PARTY-NOTICES.md` — полные лицензии PDFium, его компонентов и .NET, включаемые в публикацию.
- `.gitignore` — исключения для результатов сборки и локальных настроек.
- `AGENTS.md` — инструкции для работы с проектом.

## Сборка и запуск
На Windows с .NET 10 SDK и Visual Studio 2022/2026 C++ Build Tools (MSVC x64, Windows SDK, CMake):

```powershell
dotnet restore PDF_Reader/PDF_Reader.slnx --locked-mode
dotnet build PDF_Reader/PDF_Reader.slnx -c Release --no-restore
dotnet run --project PDF_Reader/PDF_Reader
dotnet run --project PDF_Reader/PDF_Reader.Tests -- artifacts/tests
# Необязательно: реальные пользовательские 3D PDF, только чтение:
dotnet run --project PDF_Reader/PDF_Reader.Tests -- artifacts/tests --3d-samples "каталог PDF 3D"
.\tools\Build-3D.ps1 -Test # Регрессии PRC без пользовательских файлов
.\tools\Publish.ps1
```

Публикация: `artifacts/PaperDesk/PaperDesk.exe`, переносить всю папку. Тесты не отправляют задания на физический принтер; проверяют пагинацию, геометрию постера/склейки, раскладку брошюры и рендеринг для печати. Необязательный аргумент `--printer-check` после каталога тестов проверяет реальные возможности установленных очередей без отправки заданий. PNG интерфейса и сгенерированные PDF находятся в `artifacts/tests`. Команды WPF следует выполнять на Windows с доступным рабочим столом.

## Реализованные возможности
- Начальный 3D-просмотр U3D без сжатия и PRC: отдельное окно, вращение/сдвиг/приближение, стандартные ракурсы, матовый/глянцевый/металлический/иллюстрационный/каркасный режимы, свет/блеск/фон и сечение. Растр модели появляется на странице, в миниатюрах и при печати. Меню «Вид» содержит просмотр и настройки ГП. По умолчанию приоритет дискретной графики, встроенная используется при отсутствии дискретной; доступен явный адаптер и программный WARP. Сохранённый выбор применяется к вновь открываемым 3D-окнам и новым предпросмотрам.
- PRC-сборки учитывают иерархию экземпляров, наследование размещения от прототипа, глобальные ссылки на геометрию разных file structures и локальные координаты RI, включая поворот/масштаб. Собранный и разнесённый PRC из SolidWorks 2018 проверены на реальных документах.
- Светлая/тёмная тема в стиле Windows и режим «Как в Windows»; переключение через меню «Вид», сохранение выбора, обновление при смене системной темы. Цвет страниц PDF и миниатюр сохраняется.
- Вкладки, перетаскивание файлов, открытие PDF через аргументы, `/p` для диалога печати. Повторный запуск открывает файлы во вкладках уже работающего окна.
- Виртуализованный непрерывный просмотр и миниатюры, масштабирование, поворот, полноэкранный режим. При крупном масштабе — основа низкого разрешения и резкий фрагмент видимой области. Ползунки прокрутки документа и панелей сохраняют минимальную длину 40 единиц WPF при любом числе страниц и изменении размера окна.
- Иерархические PDF-закладки, поиск с подсветкой всех совпадений на странице, регистр и слово целиком, выделение и копирование.
- Замена/удаление текстовых объектов с сохранением исходного шрифта, если в нём есть нужные символы; иначе встраивается подмножество Segoe UI. Добавление кириллического и многострочного текста.
- Аннотации: заметка, маркер, подчёркивание, зачёркивание, прямоугольник, овал, карандаш; цвет и толщина линии на панели. Редактирование: выделение щелчком, перетаскивание (фигуры, рисунки, заметки), изменение размера прямоугольника и овала, смена цвета, комментарий (двойной щелчок), удаление (Delete). Список всех типов markup-аннотаций, удаление вместе с popup. AcroForm: текст, флажки, переключатели, редактируемые выпадающие поля.
- Создание, вставка, перемещение, удаление, импорт и извлечение страниц.
- Атомарное сохранение, конфликт с внешними изменениями файла, undo/redo и сохранение паролей PDF. Подписанные PDF сохраняются инкрементально; сохранение без изменений не переписывает байты файла.
- Автосохранение резервных копий изменённых документов раз в минуту и при сбое; восстановление при следующем запуске.
- Асинхронная печать с собственным предпросмотром, выбором принтера/бумаги, ориентацией, копиями, дуплексом, оттенками серого, смешанными диапазонами, чётными/нечётными страницами и обратным порядком. Размер: вписать/100 %/уменьшить/свой масштаб. Постер: автоматическое разбиение больших страниц, нахлёст рисунка, отдельные поля под склейку с четырёх сторон, метки обрезки и координаты строка-столбец на верхнем/нижнем поле; карта плиток в предпросмотре. Несколько страниц на листе: сетка, порядок, рамки. Брошюра: раскладка со вставкой пустых страниц, обе стороны с дуплексом или отдельные стороны вручную.
- Недавние документы/последняя страница; регистрация для текущего пользователя и выбор приложения по умолчанию через настройки Windows.

## Границы реализации
3D пока не воспроизводит все возможности Acrobat: сжатый/прогрессивный U3D, анимации, текстуры, PDF/3D JavaScript, редактирование/экспорт моделей, исходные камеры PDF и PRC без готовой треугольной геометрии не поддержаны. На странице поддержана одна 3D-аннотация с U3D/PRC и без фильтра или с FlateDecode. Если положение PRC-ресурса в сборке не разрешено, он показывается в собственных координатах с предупреждением; полностью разрешённые сборки этого предупреждения не показывают. Проективные матрицы PRC отклоняются. 3D-растр ограничен 2048 пикселями по длинной стороне; печать использует начальный ракурс, а не текущую камеру отдельного окна.
OCR, редактирование вложенных Form XObjects/изображений, перевёрстка абзацев, XFA, создание цифровых подписей и экспорт в Office отсутствуют. Замена текста сохраняет позицию, цвет, обводку, матрицу и режим отрисовки; межсимвольный интервал и масштаб по горизонтали не переносятся, длинный текст не переносится автоматически. Символы вне Segoe UI (например, CJK) отклоняются с сообщением. В подписанном PDF подписанная ревизия остаётся неизменной, но правки содержимого валидатор покажет как изменения после подписи; в инкрементальных обновлениях удалённое содержимое остаётся в предыдущих ревизиях файла. Печать растром в 200 DPI. Снимки истории: до 20 состояний и ориентир 128 МБ, минимум один снимок для крупного PDF. Замена текста не является инструментом безопасной redaction.

## Архитектурные правила
- PDFium не потокобезопасен: все обращения к нативному движку сериализованы общим lock; тяжёлые операции выполняются вне UI-потока.
- 3D не выполняет JavaScript и не изменяет PDF. Снимок байтов/пароль/границы аннотации берутся в PDF-сервисе вне UI-потока; отдельный парсер работает после отпускания PDFium lock. Для границ используется PDFium с учётом поворота страниц. D3D11 имеет собственную сериализацию и SafeHandle; никаких GPU/worker операций под PDFium lock.
- Работник PRC обходит экземпляры сборки: собственная матрица экземпляра заменяет матрицу прототипа (включая явную единичную), реальные уровни parent/child перемножаются. `biased_tess_index` локален для file structure; геометрия разрешается через `part_detail_index`, а локальные системы RI — через `prc_api_part_local_transform`. Нормали рассчитываются после преобразования треугольников. Патчи nanoPRC и проверки входят в соответствующие исходники публикации.
- Декодер работает отдельным процессом без окна: 90 секунд, job object с памятью процесса до 2 ГБ и завершением при закрытии владельца. Один декодер одновременно; поток до 256 МБ, до 15 млн вершин, проверяются длины/индексы/конечность чисел. Временный каталог создаётся для операции и удаляется после завершения; пароли туда не записываются. AGPL-исходники работника, все его изменения и самостоятельная сборка сохраняются в third-party при публикации.
- UI-поток не берёт lock PDFium: `IsDirty`, `CanUndo`, `CanRedo`, `PageCount` и `Revision` публикуются в поля после каждого изменения. Файловый ввод-вывод при сохранении выполняется вне lock.
- Снимок истории использует загруженный буфер, пока он соответствует состоянию; сериализация нужна только после изменения. Сохранение подписанного PDF (`SavesIncrementally`) — только инкрементальное, остальные PDF переписываются целиком.
- Новый текст встраивает подмножество шрифта для каждого изменения; не встраивать шрифт целиком и не держать PDFium-шрифт открытым между изменениями. Исходный шрифт объекта использовать до его удаления.
- Изменение одной страницы передаёт её индекс в `ChangeAsync`: элементы страниц переиспользуются, перечитываются аннотации только этой страницы, позиция прокрутки сохраняется.
- Внешний вид аннотаций (AP) генерирует PDFium: после создания и изменения вызывается `GenerateAppearances`. Для смены цвета или размера AP удаляется и создаётся заново; перемещение сдвигает только Rect (и ink-штрихи), AP отображается в новый Rect. `FPDFAnnot_GetColor` не работает при наличии AP — цвет читается из объектов AP. Значок заметки PDFium всегда жёлтый, поэтому заметки не перекрашиваются. Разметка текста не перемещается.
- Правка аннотации проверяет, что запись `PdfComment` (индекс, тип, текст, автор, границы, цвет) совпадает с документом; после изменения страницы выбор восстанавливается по индексу, после удаления на странице — сбрасывается.
- Крупные страницы рендерятся фрагментом видимой области (`RenderRegion`); полный растр ограничен `MaxRenderPixels` с сохранением пропорций.
- Предпросмотр и печать используют один `PrintPlan` и один механизм размещения листов; тяжёлое чтение принтера и рендеринг — вне UI-потока. Для постера `RenderRegion` вызывается с флагами печати; поля под склейку не смешиваются с нахлёстом изображения. Координаты плиток — строка-столбец от верхнего левого угла страницы PDF, без автоповорота содержимого постера. План ограничен 10 000 сторон. При отсутствии области печати от драйвера — поля 5 мм с сообщением; при отсутствии принтера — только предпросмотр. Перед закрытием копии документа дождаться всех запросов предпросмотра и печати.
- Резервные копии не содержат паролей; копии работающего процесса не предлагаются к восстановлению. Named pipe единственного экземпляра доступен только текущему пользователю.
- PDF открыт из удерживаемого буфера памяти: исходный файл не блокируется и сохраняется атомарно через временный файл в том же каталоге.
- Изменения PDF выполняются транзакционно с откатом при ошибке, ограниченной историей undo/redo и отдельным признаком несохранённых изменений.
- PDF-координаты преобразуются через PDFium, включая поворот страниц. Масштаб UI не должен влиять на координаты изменений.
- UI не обращается напрямую к P/Invoke. Нативные указатели не выходят из PDF-сервиса.
- Панели и всплывающие элементы используют шаблоны приложения с динамической палитрой, а не светлые анимированные фоны Aero. При смене темы обновляются цвета постоянных кистей; фон HwndTarget обновляется вместе с заголовком, чтобы открытые и перерисовываемые области окна не вспыхивали белым. Цвета и белый фон PDF/печатного листа от темы не зависят.
- Подключать и отключать каждую страницу в FormFillSession до закрытия PDFium page handle; callback-делегаты и структуры удерживать до закрытия form environment.
- Не считать reserved permission bits разрешением для PDF security revision 2: сборка страниц определяется правом изменения, заполнение формы — правом аннотирования.
- Обновлять ObservableCollection только в UI-потоке; импорт, поиск, чтение метаданных и рендеринг выполняются вне него. Изменение коллекции вкладок блокирует обратные callbacks выбора до завершения обновления.
- Не менять Windows UserChoice напрямую и не регистрировать ассоциации при запуске: это выполняется только по явному нажатию кнопки пользователем.
- Файлы `bin`, `obj`, `.packages`, `.dotnet_home`, `artifacts`, `.vs` и `*.user` не должны попадать в репозиторий.

- После изменения архитектуры, структуры, зависимостей, команд сборки или возможностей обновлять оба файла в одной задаче.
- Перед завершением работы проверять равенство содержимого обоих файлов. Не оставлять изменения только в одном из них.
